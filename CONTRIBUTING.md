# Как участвовать в разработке MegaTool

Спасибо за интерес к проекту. MegaTool — небольшой self-hosted инструмент:
мы ценим аккуратные, локальные изменения, которые не добавляют обязательных
внешних сервисов и не усложняют запуск.

## Требования

- Python 3.8+ и Git.
- Docker, Kubernetes, Ansible, nginx и SSH-клиент **не обязательны** для
  разработки и тестов.
- Node.js и сборщик не используются: интерфейс — обычные ES-модули в `web/js`.

## Запуск и окружение

Пользовательский запуск одной командой:

```bash
python start.py
```

Разработческое окружение:

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File scripts\bootstrap.ps1 -Dev
```

```bash
# Linux / macOS
bash scripts/bootstrap.sh --dev
```

Либо вручную:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux:   source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

## Обязательные проверки перед PR

```powershell
# Windows
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check megatool tests
.venv\Scripts\python.exe scripts\jscheck.py
```

```bash
# Linux / macOS
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check megatool tests
.venv/bin/python scripts/jscheck.py
```

Все три проверки должны проходить. Если менялись только документы, достаточно
проверить ссылки и орфографию, но CI всё равно запустит полный набор.

Отдельно можно прогнать симуляцию запуска на 10 профилях Windows, Linux и
macOS (она также входит в pytest):

```powershell
.venv\Scripts\python.exe scripts\startup_matrix.py  # Windows
.venv/bin/python scripts/startup_matrix.py          # Linux/macOS
```

## Правила кода

### Python

- Поддерживается Python 3.8+; не используйте синтаксис и API, требующие более
  новой версии (`list[...]`, `X | None`, `Path.is_relative_to`,
  `write_text(newline=...)`, `functools.cache` и т. п.). Для аннотаций — `typing`.
- Следуйте стилю соседнего кода: type hints, короткие функции, понятные имена.
- Новые runtime-зависимости добавляйте только с обоснованием в PR; проект
  намеренно обходится минимумом пакетов.
- Внешние команды запускайте без `shell=True`, с проверкой аргументов и
  таймаутов. Опасные действия должны попадать в аудит.
- Пользовательские пути проверяйте через существующие песочницы, не используйте
  `..` и абсолютные пути без валидации.

### JavaScript

- Только ванильный JavaScript и ES-модули. Никаких CDN, npm-зависимостей,
  inline-скриптов и этапа сборки.
- Не добавляйте `innerHTML` для недоверенных данных: используйте существующие
  DOM-хелперы и экранирование.
- Сохраняйте стиль компонентов из `web/js/ui.js` и `web/js/views/`.
- Новые строки интерфейса добавляйте одновременно в `web/js/lang/ru/` и
  `web/js/lang/en/`; `jscheck` проверяет синтаксис, а тесты — полноту словарей.

### Локализация

- Серверные сообщения — через `t("module.key")` и словари
  `megatool/lang/{ru,en}_*.py`.
- Не вставляйте пользовательские данные в переводимую строку без параметров:
  используйте подстановки, чтобы не ломать экранирование.
- Проверяйте оба языка, даже если PR в первую очередь для одного из них.

## Безопасность

- Не коммитьте `.env`, `config.json`, токены агентов, приватные ключи, дампы и
  логи с персональными данными.
- Для уязвимостей используйте [SECURITY.md](SECURITY.md), а не публичный Issue.
- Изменения песочницы файлов, парсеров настроек и запуска команд сопровождайте
  тестами на запрет доступа и обход валидации.
- Не ослабляйте проверки Host/Origin, CSP, лимиты запросов и права `0600` без
  серьёзной причины. Встроенной аутентификации в проекте нет — не добавляйте
  самодельные пароли/сессии без отдельного обсуждения.

## Pull request

1. Сделайте небольшую ветку от `main`.
2. Опишите, что и зачем изменилось, и как это проверено.
3. Добавьте или обновите тесты; для UI приложите скриншот, если он помогает
   ревью.
4. Обновите документацию (`README.md`, `docs/`) и `CHANGELOG.md`, если изменение
   заметно пользователю.
5. Убедитесь, что в diff нет секретов, `.venv`, кэшей и локальных конфигов.

Коммиты и PR можно писать по-русски или по-английски. Главное — понятное
описание и воспроизводимая проверка.
