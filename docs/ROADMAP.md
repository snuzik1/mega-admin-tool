# Планы развития MegaTool

Документ фиксирует состояние v0.9.0 и порядок дальнейших работ. Приоритет —
эксплуатационная надёжность и понятность интерфейса, затем функциональные
пробелы, затем масштабные направления. Проект поддерживает только Linux;
исторические разделы ниже описывают состояние на момент соответствующей версии.

## Выполнено (v0.9.0)

**Удалённый доступ и TLS**
- Встроенный HTTPS в uvicorn (`ssl_certfile`/`ssl_keyfile`) без обязательного
  обратного прокси. Настройки — в `server.tls`; внешний bind без TLS
  запрещён, кроме явного `--allow-insecure-remote`.
- Самоподписанный сертификат генерируется через `openssl` (SAN для loopback,
  имени машины, локальных IP, bind-адреса и `allowed_hosts`), поддерживаются
  собственные PEM-файлы. Ключ — `0600`, каталог `tls/` — `0700`, symlink
  отклоняется; сертификат и ключ проверяются до запуска uvicorn.
- Мастер `--setup` для локального HTTP или LAN HTTPS; CLI
  `--tls-cert`/`--tls-key`; API `POST /api/settings/tls/generate`; карточка
  TLS в настройках (статус, отпечаток, срок, генерация, включение/выключение).
- HSTS для HTTPS; Host allowlist работает при внешнем bind; локальные имена и
  IP разрешаются автоматически.
- `install.sh`/Docker ставят `openssl`/`ca-certificates`; systemd-скрипт
  определяет схему; backup/restore включают `tls/` и восстанавливают права
  ключа.
- Тесты TLS, внешнего bind, API, HSTS и backup; документация обновлена.

## Выполнено (v0.8.0)

**Аутентификация**
- Одна учётная запись `admin` с полным доступом ко всем разделам; ролей и
  отдельных пользователей нет.
- Пароль задаётся в терминале при первом запуске и запрашивается при следующих;
  хранится только как PBKDF2-SHA256-хеш (600 000 итераций) в
  `~/.megatool/auth.json` (`0600`, каталог `0700`). При чтении проверяются
  владелец, права, регулярность файла и отсутствие символической ссылки.
- Веб-вход на отдельном экране, выход из верхней панели, обработка истечения
  сессии. Сессии в памяти на 12 часов, cookie `HttpOnly`/`SameSite=Strict`,
  5 неудачных попыток за 60 секунд, аудит входов/выходов.
- Все `/api/*`, кроме health/status/login, и WebSocket закрыты без сессии;
  API отвечает `401`, сокет — `4401`.
- CLI: `--set-password`, `--auth-status`, `--no-login-prompt`, `--auth-file`;
  env: `MEGATOOL_AUTH_FILE`, `MEGATOOL_ADMIN_PASSWORD`, `MEGATOOL_NEW_PASSWORD`,
  `MEGATOOL_AUTH_ITERATIONS`, `MEGATOOL_SECURE_COOKIE`.
- `scripts/install-autostart.sh` требует готовый `auth.json`, передаёт пути в
  systemd и запускает с `--no-login-prompt`; smoke проверяет `401` и вход.
- Тесты: файл секрета и права, хеш, вход/выход, rate limit, urlencoded,
  закрытый API/WebSocket, живой uvicorn с cookie.

**Прочее**
- Версия 0.8.0; документация обновлена, утверждения об отсутствии входа удалены.

## Выполнено (v0.7.0)

**Python 3.8 и совместимость**
- Минимальная версия Python снижена с 3.10 до 3.8: PEP 585/604-аннотации
  переведены на `typing`, `Path.is_relative_to` и `write_text(newline=...)`
  заменены совместимыми helper-функциями, `cancel_futures` убран.
- Зависимости закреплены диапазонами, поддерживающими 3.8; CI проверяет
  Python 3.8, 3.12 и 3.14 на Ubuntu; `start.py` проверяет версию
  как снаружи, так и внутри существующего `.venv`.

**Удаление системы доступа**
- Полностью удалены `access.py`, `api_access.py`, `localauth.py`, раздел
  **Доступ**, окна входа/первого владельца/смены пароля, пресеты, сессии и
  мастер-токен. Пользователи, пресеты и сессии больше не создаются. (В 0.8.0
  возвращена одна учётная запись администратора, но не прежняя система ролей.)
- `auth` вырезается из загружаемого конфига, экспорта и обновлений; PATCH и
  импорт принимают только известные секции. Серверные и клиентские словари
  очищены от строк доступа.
- Сохранены Host/Origin, CSP, лимит тела, песочница файлов, аудит, а также
  отдельные токены удалённых агентов мониторинга.

**Оптимизации**
- Кэш шаблонов переводов в `i18n.py` и кэш разбора точечных путей в `config.py`.
- Один HTTP-middleware вместо трёх: Host/Origin, лимит тела и заголовки
  безопасности за один проход; с горячего пути API убраны проверки прав.
- Удалены лишние ветки и импорты, связанные с авторизацией.

**Прочее**
- Полный набор тестов, jscheck и ruff зелёные; версия 0.7.0.
- Поддержка ограничена Linux: Windows/macOS-ветки, обёртки и PowerShell-скрипты
  удалены, CI и симуляция запуска переведены на Linux-профили.
- Интерфейс перенесён в `megatool/web/`, входит в wheel как package-data;
  CI проверяет содержимое wheel и установку в чистое окружение.
- `MEGATOOL_VENV` понимают `start.py`, `bootstrap.sh` и
  `install-autostart.sh`; добавлены подсказка и smoke-проверка для Alpine.
- `install.sh` автоматически ставит системные пакеты через apt/dnf/yum,
  pacman, apk или zypper; `run.sh` на POSIX `sh` вызывает его только при
  отсутствии Python/venv. Проверено в чистом Alpine-контейнере.
- `quickstart.sh` скачивает архив репозитория без git и запускает MegaTool
  одной командой; поддерживает обновление, выбор ветки/тега и каталога
  установки.
- Python 3.8 остаётся минимальным для старых дистрибутивов, хотя upstream
  больше его не поддерживает; повышение версии вынесено в отдельное решение.

## Выполнено (v0.6.0)

**Локальные пользователи, владелец и первый вход**
- Новый модуль `localauth.py`: проверка существования локальной учётной записи
  и прав root/sudo/wheel на Linux, включая процесс без повышения прав.
- Первый **владелец MegaTool** создаётся только с loopback, при пустом списке
  пользователей и привилегированной учётной записи процесса. Оператор сам
  вводит непустой логин и пароль MegaTool; системный пароль не используется.
  Владелец получает полный пресет «Администратор» и флаг `owner`. Мастер первого
  входа и кнопка в **Настройках → Сервер**.
- Только владелец может создавать администраторов и других владельцев, менять
  административные пресеты и трогать аккаунты владельцев. Рядовой администратор
  с `access:manage` создаёт обычных пользователей, но не может выдать
  административный пресет или повысить себя. Последнего включённого владельца
  нельзя удалить, выключить или лишить флага. В старом `access.json` без флага
  владельцем автоматически становится первый включённый администратор с
  управлением доступом и настройками.
- `auth.local_only`: после первичной настройки каждый пользователь обязан быть
  привязан к локальной учётной записи с правами администратора; привязка
  перепроверяется при входе. Старые внутренние пользователи остаются доступны
  только при явно выключенном `local_only`.
- Смена собственного пароля из верхней панели требует старый пароль, отзывает
  все сессии и возвращает новую. Администратор больше не может менять или
  сбрасывать пароль другого пользователя через форму редактирования.
- В разделе **Доступ** отображаются владелец, локальная учётная запись и её роль;
  в форме пользователя — флаг владельца для владельца, выбор/проверка локальной
  учётки, без поля смены пароля.
- API: публичные `/api/auth/setup-status` и `/api/auth/setup`, защищённый
  `POST /api/auth/password`; проверка владельца в `save_users` и `save_presets`;
  новые сообщения локализованы на RU/EN.
- Новый [docs/GUIDE.md](GUIDE.md): краткие инструкции по всем 15 разделам.

**Прочее**
- 106 тестов, jscheck и ruff зелёные; версия 0.6.0.
- Репозиторий подготовлен к публикации на GitHub: CI для Linux,
  Dependabot, шаблоны Issue/PR, `SECURITY.md`, `CONTRIBUTING.md`,
  `CHANGELOG.md` и [docs/PUBLISHING.md](PUBLISHING.md).

## Выполнено (v0.5.0)

**Мониторинг произвольных серверов**
- Новый раздел **Серверы**: свободный инвентарь машин и сервисов (имя, тип,
  заметка, включён/выключен), TCP- и HTTP(S)-пробы.
- HTTP: ожидаемый код, ключевое слово, проверка TLS; только HTTP(S), не более
  трёх перенаправлений и 64 КБ тела; без логина/пароля в URL.
- Индивидуальные интервалы 15–3600 с и таймауты 1–10 с, до 50 записей.
- Текущее состояние, uptime, простой и время в выключенном состоянии; итоги
  переживают перезапуск в `hosts_state.json`, конфигурация — в `hosts`
  (отдельно от `servers` для SSH-провижининга).
- Ручной запуск одной записи/всех, карточка на дашборде, сводка в `/api/state`,
  алерты с дедупликацией `host:<id>` и системные уведомления браузера.

**Пользователи, пресеты прав и вход**
- Новый раздел **Доступ**: пресеты с матрицей «раздел → нет/просмотр/управление»
  по 15 разделам, создание пользователей с назначением пресета.
- `access.json` с правами `0600`: PBKDF2-SHA256 (210 000 итераций), пароли и
  хэши никогда не возвращаются API и не входят в экспорт настроек.
- Три стартовых пресета: «Наблюдатель», «Оператор», «Администратор»; удаление
  используемого пресета запрещено.
- Вход по логину/паролю, сессии на 12 часов в памяти, отзыв при смене пароля,
  выключении и удалении пользователя; мастер-токен остаётся путём
  восстановления.
- Серверный RBAC для HTTP и WebSocket: уровни view/manage, карта API → раздел,
  fail-closed для неизвестных `/api/*`; ротация/отключение мастер-токена только
  для master/local.
- Интерфейс: загрузка `/api/auth/me`, фильтрация меню, окно входа, индикатор
  пользователя и выход, скрытие управляющих кнопок в ключевых разделах.

**Прочее**
- 102 теста, jscheck и ruff зелёные;
  версия 0.5.0.

## Выполнено (v0.4.0)

**Проверки доступности**
- Новый раздел «Проверки сервисов»: HTTP(S)-адреса, TCP-порты и TLS-сертификаты.
- Проверки хранятся в `checks` конфигурации, выполняются фоновым потоком по
  индивидуальному интервалу (15–3600 с), таймауты 1–10 с, до 50 проверок.
- HTTP: ожидаемый код, поиск строки в теле, лимит тела 64 КБ, не более трёх
  перенаправлений только на HTTP(S), без прокси и учётных данных в URL.
- TCP и TLS: определение открытого порта, срока сертификата и предупреждение
  за N дней; для внутренних self-signed сертификатов проверку можно отключить.
- История в памяти (40 точек), ручной запуск одной проверки или всех, карточка
  на дашборде, алерты коллектора, экспорт отчёта в JSON и CSV.

**Темы и настройки**
- Темы: светлая, сепия, сталь, тёмная, контрастная и авто; переключение из
  настроек и верхней панели, `color-scheme` для системных элементов.
- В **Настройки → Сервер** добавлены `server.allowed_hosts` (имена для
  обратного прокси), в **Настройки → Система** — ротация аудита
  (`audit.max_mb`, `audit.keep`) и лимиты задач (`jobs.max_active`, `jobs.keep`).
- Все числовые поля валидируются на сервере, изменения применяются без
  перезапуска (кроме адреса/порта сервера).

**Безопасность**
- CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`,
  `Permissions-Policy` и COOP/CORP для всех ответов; отдельная политика для
  Swagger UI.
- WebSocket проверяет `Origin` (защита от CSWSH) в дополнение к `Host` и токену.
- `config.json` и каталог с журналами закрываются правами `0600`/`0700`.
- `PATCH /api/settings` не меняет `auth`; импорт настроек проходит ту же
  валидацию, что и PATCH, и не позволяет включить токен в обход ротации.
- Секции настроек проверяются на тип, порт и допустимые значения — испорченный
  JSON или строка вместо объекта больше не роняют API.

**Прочее**
- Исправлен `--home`: каталог применяется до импорта конфигурации.
- 96 тестов, jscheck и ruff зелёные;
  версия 0.4.0.

## Выполнено (v0.3.0)

**Стабильность**
- Смена языка больше не оставляет смешанный интерфейс: при открытом черновике
  страница перезагружается, черновики в `sessionStorage` сохраняются.
- Кэши отчёта «Изменения» и сведений о системе сбрасываются при смене языка.
- Лимит одновременных задач `jobs.max_active` (по умолчанию 8) с понятной
  ошибкой 429 вместо неограниченного роста потоков.
- Защита от перебора токена: 10 ошибок за минуту → 429 на минуту; токен в query
  принимается только для WebSocket, ZIP скачивается с заголовком.
- Явные сообщения об ошибках валидации списка агентов и настроек.

**Мобильная адаптация**
- Бургер-меню с выдвижной панелью, затемнением и закрытием по Esc/выбору
  раздела; на десктопе поведение не меняется.
- Адаптивные карточки, таблицы с горизонтальной прокруткой, модальные окна,
  формы, редактор конфигов и тосты на экранах до 900/560/380 px.

**Удалённые агенты мониторинга**
- `scripts/megatool-agent.py` — один файл без зависимостей (stdlib; psutil
  опционален): CPU, память, swap, диск, сеть, uptime, load, температура.
- Токен, `/health`, кэш метрик, поддержка Linux.
- API `/api/agents` и `/api/agents/test`, карточка на дашборде, управление в
  **Настройки → Агенты**, маскирование токенов, валидация адресов, лимит 20.
- Параллельный опрос с таймаутом 3 с и кэшем 5 с: недоступная машина не
  тормозит остальные и не нагружает API.

**Интеграционные тесты**
- Полный жизненный цикл набора конфигов через приложение (создание, файл,
  ZIP, удаление).
- Настоящий агент на локальном HTTP-сервере + API и сохранение токена.
- Лимит задач, троттлинг токена, живой uvicorn с WebSocket.

**Автозапуск**
- Пользовательская служба systemd (`install-autostart.sh`), опция `--linger`,
  корректное завершение по SIGINT.
- Скрипт удаления и раздел в README.

**Прочее**
- 83 теста, jscheck и ruff зелёные; версия 0.3.0.

   сейчас покрыты dry-run, генерация скриптов, валидация и подмена `run_remote`
   (API-интеграция при этом уже есть).
3. **Черновики всех вкладок редактора.** Сейчас подтверждение ухода проверяет
   активный файл; нужно учитывать все «грязные» вкладки сразу.
4. **Долговременная история проверок и серверов.** Сейчас результаты живут в
   памяти, а у серверов на диске только агрегаты; нужен компактный журнал
   доступности за сутки/неделю и графики.
5. **Аудит доступности остальных разделов.** Экран входа и основные формы
   проверены Lighthouse и клавиатурой; для таблиц, редакторов и модальных окон
   нужно пройти тот же чек-лист (landmark, focus trap, aria-live, контраст).

## Доступ (после 0.9.0)

Одна учётная запись `admin` с полным доступом — простая модель для self-hosted
инструмента, а не многопользовательская система. Пароль хранится только как
PBKDF2-хеш, сессии живут в памяти, все API/WebSocket закрыты. Для удалённого
доступа используйте встроенный HTTPS (`--setup`/настройки/`--tls-cert`), VPN
или SSH-туннель; `MEGATOOL_SECURE_COOKIE=1` нужен только при TLS-терминации
внешним прокси. Не публикуйте порт в интернет без TLS и firewall.

Если понадобится многопользовательский режим, его стоит проектировать как
отдельный слой: OIDC/LDAP или доверенный обратный прокси, без возврата
самодельных ролей, пресетов и мастер-токена.

## Дальше

- **Балансировщик**: TLS-терминация, сохранение метрик между перезапусками,
  вынос в отдельный процесс, чтобы падение прокси не затрагивало API.
- **Мониторинг**: экспорт метрик агентов в Prometheus, длительное хранение
  истории (сейчас — кольцевой буфер в памяти), графики по удалённым машинам.
- **Многопользовательский режим**: только как внешний слой (OIDC/LDAP или
  аутентифицирующий прокси) с журналом по пользователям; встроенную систему
  ролей и пресетов возвращать не планируется.
- **Плагины**: рецепты и задачи из внешних каталогов с подписью, пользовательские
  шаблоны наборов и конфигов.
- **Автоматизация**: планировщик задач (cron), деплой по git-хуку.
- **Проверки сервисов**: клавиатурная навигация по таблицам, горячие клавиши для
  разделов, экранный диктор (aria-атрибуты).

## Известные ограничения

- Балансировщик живёт в процессе MegaTool: при перезапуске приложения прокси
  останавливается.
- Обновление пакетов и настройка серверов выполняются по SSH синхронными
  задачами; долгие операции (обновление системы) могут превысить таймаут задачи.
- Kubernetes-раздел требует `kubectl` в PATH или в настройках; in-cluster
  конфигурация не поддерживается.
- Внешние инструменты вызываются без shell; сложные пайплайны на удалённых
  машинах выполняются через свободную команду или Ansible.
