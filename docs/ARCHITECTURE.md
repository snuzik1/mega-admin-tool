# Архитектура MegaTool

## Общая схема

```
браузер (интерфейс без сборки)          Python-процесс (один порт)
┌──────────────────────────┐            ┌────────────────────────────────────┐
│ web/index.html + ES-мод. │  HTTP/WS   │ FastAPI: /api/*  + статика web/    │
│ 14 разделов, canvas-граф.│◄──────────►│ runtime: collector, checks, hosts, │
│ тема, плотность, RU/EN,  │            │ containers, balancers, catalog,    │
│ мобильное меню           │            │ bundles, servers(SSH), agents, k8s,│
└──────────────────────────┘            │ ansible, jobs, workspace, i18n     │
                                        └───────┬────────────────────────────┘
                                                │ subprocess без shell
                     docker / podman / kubectl / ansible-playbook / nginx / ssh
```

Один процесс владеет и API, и интерфейсом: нет Node.js, нет сборки, нет CDN.
Всё, что требует внешних инструментов, вызывается подпроцессами без shell и
деградирует предсказуемо: нет `kubectl` — раздел Kubernetes показывает
подсказку, остальное работает.

## Backend

| Файл | Ответственность |
| --- | --- |
| `__main__.py` | CLI (`--host/--port/--home/--config/--reload`), баннер, запуск uvicorn |
| `server.py` | сборка FastAPI: `/api`, WebSocket, статика (без кэша), проверка `Host`/`Origin`, лимит тела запроса и заголовки безопасности в одном middleware |
| `runtime.py` | `build_runtime`: настройки + все сервисы; язык, ротация аудита, «заметки» о нехватке инструментов |
| `config.py` | `DEFAULT_CONFIG`, пути `MEGATOOL_HOME` (`config.json`, `hosts_state.json`, `apps/`, `bundles/`, `configs/`, `runs/`, `logs/`), миграция `~/.megapet`, вырезание устаревшего `auth`, кэш разбора точечных путей |
| `collector.py` | опрос psutil, кольцевая история, алерты; тяжёлые обходы процессов кэшируются (число потоков 15 с, список 2 с), топ процессов собирается в два прохода |
| `checks.py` | проверки доступности: HTTP(S)/TCP/TLS, фоновый поток, история 40 точек, сводка и алерты |
| `api_checks.py` | маршруты `/api/checks` (чтение, сохранение, ручной запуск) |
| `hosts.py` | инвентарь серверов: TCP/HTTP-пробы, enabled/disabled, накопленные uptime/downtime/disabled, `hosts_state.json`, алерты |
| `api_hosts.py` | маршруты `/api/hosts` (чтение, сохранение, ручной запуск одной записи или всех) |
| `systeminfo.py` | сведения о системе, диски, температура, сеть |
| `changes.py` | отчёт «что изменилось»: файлы, пакеты, входы, сервисы, журналы, аудит; ротация `logs/audit.jsonl` (`audit.max_mb`, `audit.keep`) |
| `containers.py` | docker/podman: список, stats, логи, inspect, действия, compose, df/образы/тома/сети |
| `balancer.py` | `Balancer` (реальный прокси на asyncio) + `BalancerManager` |
| `recipes.py` | 29 рецептов: метаданные, переменные, рендер шаблонов, английские названия/описания |
| `catalog.py` | развёртывание/удаление приложений, статус compose-стека, применение манифестов |
| `appfiles.py` | шаблоны конфигов (13 шт.), валидаторы (nginx/compose/yaml/k8s) |
| `bundles.py` | наборы конфигов: хранилище `bundles/<id>/`, 5 шаблонов, экспорт в ZIP, песочница имён файлов |
| `api_bundles.py` | маршруты `/api/bundles/*` (ленивый `BundleStore` на runtime) |
| `agents.py` | опрос удалённых агентов: нормализация адресов, параллельные запросы с таймаутом, кэш 5 с, маскирование токенов |
| `api_agents.py` | маршруты `/api/agents` и `/api/agents/test` |
| `provision.py` | SSH: проверка сервера, 10 задач, генерация sh-скрипта и Ansible-плейбука, `ServersManager` |
| `api_servers.py` | маршруты `/api/servers/*` (CRUD, check/run/exec/playbook, аудит) |
| `k8s.py` | kubectl: обзор (параллельные запросы), узлы/поды/сервисы/события, действия, apply; кэш с single-flight |
| `ansible.py` | инвентарь (парсер), плейбуки, запуск, ping/check |
| `jobs.py` | менеджер долгих операций: лимит одновременных задач (`jobs.max_active`), живые логи, отмена, история, stdin для скриптов |
| `security.py` | определение loopback-адресов (`is_loopback`) для проверок `Host`/`Origin` |
| `i18n.py` | серверная локализация: `t()`, `set_language()`, автосборка словарей из `lang/`, кэш шаблонов, `audit()` |
| `lang/ru_<модуль>.py`, `lang/en_<модуль>.py` | словари серверных сообщений (`DATA`), по файлу на язык и модуль |
| `api.py` | все HTTP-маршруты `/api/*` (тонкий слой над сервисами) |
| `util.py` | `run()` (subprocess без shell, таймауты, utf-8, stdin), `safe_id`, `which`, JSON-помощники |

### Потоки данных

* **Метрики** — `collector` опрашивает систему каждые `monitor.interval_ms` мс,
  складывает точки в кольцевой буфер (`history_points`) и рассылает их через
  WebSocket `/api/ws/metrics`. Интерфейс рисует графики без перезапросов.
* **Проверки доступности** — отдельный daemon-поток раз в секунду выбирает
  проверки, у которых истёк интервал, и запускает их в пуле из шести потоков.
  Результаты хранятся в памяти (`ChecksManager`), коллектор забирает их как
  провайдер алертов; `checks` в конфиге меняется только через валидатор.
* **Серверы** — `HostsManager` опрашивает TCP/HTTP-цели по индивидуальному
  интервалу, хранит текущее состояние и накопленные интервалы в
  `hosts_state.json`. При выключении записи текущий uptime фиксируется, а
  `disabled_sec` начинает расти; переходы `up/down` уходят в алерты с
  дедупликацией `host:<id>`. Коллектор отдаёт сводку в `/api/state`, карточка
  дашборда обновляется вместе с ним.
* **Сетевой доступ** — встроенной аутентификации нет. `security_guard` в
  одном проходе проверяет `Host` (анти-DNS-rebinding), `Origin` у изменяющих
  запросов, лимит тела и добавляет заголовки безопасности; WebSocket отдельно
  проверяет `Host`/`Origin` (CSWSH). Для удалённого доступа нужен VPN, SSH или
  обратный прокси с аутентификацией.
* **Живые задачи** — `jobs` запускает команду, пишет stdout/stderr построчно и
  раздаёт их через `/api/ws/jobs/{id}`; `runs/` хранит историю. Опциональный
  `stdin_text` пишется из отдельного потока (используется для SSH-скриптов).
* **Кэш** — `CachedK8s` (TTL 5 с, single-flight — параллельные запросы одного
  ключа не дублируют kubectl) и сводка движков: интерфейс опрашивает часто,
  инструменты дёргать не надо. Любое изменяющее действие сбрасывает кэш.
* **Аудит** — все изменяющие действия пишутся в `logs/audit.jsonl`; при
  превышении `audit.max_mb` журнал сдвигается (`audit.jsonl.1…N`), хранится
  `audit.keep` архивов.

### Балансировщик

`Balancer` — собственная реализация на `asyncio.start_server`:

* алгоритмы: round-robin, взвешенный, least-conn, ip-hash, random;
* health-checks TCP или HTTP, интервал/таймаут/ожидаемые коды;
* метрики по каждому узлу (запросы, ошибки, активные, латентность, p95);
* экспорт конфигурации в nginx / haproxy / JSON;
* `listen_port: 0` — автоматический выбор свободного порта.

Проксирование потоковое (тело не буферизуется целиком), сокеты закрываются
аккуратно в `finally` — утечек соединений нет.

## Frontend

`web/` — статические ES-модули. Ни сборщиков, ни фреймворков, ни CDN.

* `app.js` — роутер с «поколениями»: каждый переход получает свой контейнер,
  опоздавший рендер не перекрывает новый экран; тема (`data-theme`) и плотность
  (`data-density`) на `<html>`, топбар (язык, тема, уведомления), поток метрик,
  подсказки у пунктов меню, хук `beforeNavigate` (черновики редактора).
  На экранах ≤900 px боковая панель превращается в выдвижное меню (бургер,
  затемнение, закрытие по Esc/выбору раздела); на ≤560 px прячутся вторичные
  элементы топбара, карточки и таблицы перестраиваются под узкий экран.
* `css/app.css` — темы на CSS-переменных (светлая, сепия, сталь, тёмная,
  контрастная, авто) и медиазапросы для мобильных экранов (900/560/380 px),
  включая safe-area для iOS.
* `ui.js` — компоненты: карточки, таблицы (сортировка), модальные окна,
  подтверждения, тосты, чипы, формы, `guard()` (ошибки → тосты), `poller()`.
* `charts.js` — графики на canvas; цвета/штриховка читаются из CSS-переменных,
  поэтому тема переключается без перерисовки логики.
* `i18n.js` — `t("ключ", {параметры})`, `setLang()`, аудит словарей; словари
  собираются из `lang/<язык>/<раздел>.js`. На сервере шаблоны переводов
  кэшируются, чтобы не разбирать словари на каждом сообщении.
* `views/*.js` — 14 разделов; каждый `render(root)` возвращает функцию очистки
  (интервалы, подписки), которую вызывает роутер. `hosts.js` управляет
  инвентарём серверов.
* Внутри разделов с вкладками используется тот же приём «поколений», что в
  роутере (пример: `k8s.js`, `catalog.js`) — медленный запрос старой вкладки
  не перекрывает выбранную позже.
* Редактор конфигов хранит несохранённые правки в `sessionStorage`
  (`megatool.draft:<путь>`), при возврате предлагает восстановить черновик и
  спрашивает подтверждение при уходе со страницы.

## Локализация

* Язык (`ru`/`en`) — в `ui.language`, применяется на сервере (`i18n.set_language`
  из настроек при старте и при `PATCH /api/settings`) и в браузере
  (`localStorage` для мгновенного старта, сервер — источник истины).
* Backend: словари `lang/ru_*.py` / `lang/en_*.py` с `DATA`; ключи вида
  `модуль.ключ`; `t()` подставляет `{параметры}`; при отсутствии перевода
  используется русский текст. Полнота проверяется `i18n.audit()`.
* Frontend: `t("раздел.ключ")`; словари разделены по файлам, чтобы правки не
  конфликтовали. Технические значения (имена контейнеров, пути, вывод команд)
  не переводятся.
* Каталог рецептов локализуется на сервере (`recipes.localize()`), включая
  подписи и подсказки переменных; `categories()`/`kinds()` возвращают ярлыки
  на текущем языке.

## Мониторинг серверов

Раздел **Серверы** — отдельный от `checks` инвентарь: запись описывает машину
или сервис целиком (`name`, `kind`, `note`), а не отдельную проверку. Поддержаны
две пробы:

* `tcp` — открыт ли `host:port`, с таймаутом 1–10 с;
* `http` — код ответа, необязательное ключевое слово в теле (до 64 КБ) и
  проверка TLS-сертификата; допускаются только HTTP(S)-адреса без логина/пароля,
  не более трёх перенаправлений.

`HostsManager` запускает daemon-поток и пул проверок, хранит по каждой записи
`state` (`up/down/unknown/disabled`), `since`, текущие и суммарные
`uptime_sec`/`downtime_sec`/`disabled_sec`. Состояние и накопленные интервалы
атомарно пишутся в `hosts_state.json`; при выключении записи интервал uptime
закрывается, а disabled-время учитывается отдельно. Конфигурация (`hosts`)
проходит валидатор: до 50 записей, интервал 15–3600 с, безопасные имена и
адреса. API `/api/hosts` отдаёт снимок и умеет запускать одну запись или все;
ручной запуск выключенной записи игнорируется.

Коллектор получает сводку как провайдер алертов и включает её в `/api/state`.
Состояние `down` дедуплицируется ключом `host:<id>`; восстановление убирает
алерт. Интерфейс сравнивает последовательные снимки `/api/state`, поэтому
показывает уведомление браузера (если разрешено) и при падении, и при
восстановлении, а также карточку на дашборде. Это единственная связь с общим
мониторингом: сами проверки не блокируют поток метрик.

## Доступ и сетевая защита

В 0.7.0 встроенная система доступа удалена: больше нет `access.json`,
`localauth.py`, пользователей, пресетов, сессий, мастер-токена и маршрутов
`/api/auth/*`. Права на операции определяются учётной записью ОС, от имени
которой запущен процесс; интерфейс открывается без входа.

Что осталось на границе приложения:

* по умолчанию сервер слушает только `127.0.0.1`;
* HTTP-middleware `security_guard` проверяет `Host` (защита от DNS-rebinding),
  `Origin` у изменяющих запросов, лимит тела 25 МБ и добавляет заголовки
  безопасности; для loopback разрешены только loopback-имена и
  `server.allowed_hosts`;
* WebSocket-маршруты отдельно проверяют `Host`/`Origin` (защита от CSWSH);
* `Config` вырезает устаревший ключ `auth` при загрузке, обновлении и экспорте;
  `PATCH /api/settings` и импорт принимают только известные секции, поэтому
  вернуть удалённые настройки через API нельзя;
* для удалённого доступа используйте VPN, SSH-туннель или обратный прокси
  с аутентификацией и TLS; порт MegaTool не стоит публиковать напрямую.

Токены удалённых агентов — отдельный механизм: `agents.py` отправляет
`Authorization: Bearer`/`X-MegaTool-Agent-Token` агенту, а `Config.export`
маскирует сохранённые токены (`token_set`, превью). К доступу к самой консоли
эти токены отношения не имеют.

## Настройка по SSH

`provision.py` не хранит паролей: используются ключ или ssh-agent. Скрипт
собирается на сервере и передаётся на удалённую машину через `ssh ... sh -s`
(stdin), выполняется одной задачей `jobs` с живым логом. Для задач с sudo
требуется `sudo -n`; если он недоступен, фрагмент пропускается с сообщением.
Свободная команда и запуск задач блокируются настройкой
`safety.allow_remote_exec`. Тот же набор задач можно выгрузить как Ansible-
плейбук (генерация локальная, без подключения).

## Агенты мониторинга

`scripts/megatool-agent.py` — самостоятельный файл без зависимостей MegaTool
(Python 3.8+, только stdlib; `psutil` опционален для температуры и сети).
Копируется на удалённую машину и запускается:

```bash
python3 megatool-agent.py --host 0.0.0.0 --port 8791 --token СЕКРЕТ
```

* `/metrics` — JSON с CPU, памятью, swap, диском, uptime, load average, сетью,
  температурой; `/health` доступен без токена;
* токен проверяется через `Authorization: Bearer`, `X-MegaTool-Agent-Token`
  или `?token=`; без токена агент по умолчанию слушает только loopback;
* CPU считается по разнице `/proc/stat`, память — `/proc/meminfo`; кэш метрик — 1 с.

`megatool/agents.py` опрашивает настроенных агентов параллельно (до 8 потоков,
таймаут 3 с) и кэширует ответы на 5 с; недоступная машина не задерживает
остальные. Токены хранятся в `config.json`, но в API и интерфейс не попадают:
`Config.export(redact_secrets=True)` оставляет только `token_set` и превью.
Пустой токен при редактировании означает «оставить прежний».

## Автозапуск

`scripts/install-autostart.sh` пишет пользовательскую службу
`~/.config/systemd/user/megatool.service`, включает её и (по флагу
`--linger`) разрешает запуск без входа. `KillSignal=SIGINT` даёт uvicorn
корректно завершиться. Удаление — `scripts/uninstall-autostart.sh`.
Скрипт использует уже созданный `.venv` и не изменяет настройки приложения.

## Безопасность

* по умолчанию только `127.0.0.1`; встроенной аутентификации нет, поэтому
  сетевой доступ должен ограничиваться VPN, SSH-туннелем или обратным прокси
  с аутентификацией;
* защита от DNS-rebinding: пока сервер слушает loopback, `/api/*` и WebSocket
  проверяют `Host` (421) и `Origin` у изменяющих запросов (403), а WebSocket —
  ещё и `Origin` при открытии (4403); дополнительные имена — в
  `server.allowed_hosts`;
* все ответы получают CSP (без внешних скриптов; отдельное послабление только
  для Swagger UI), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`,
  `Permissions-Policy` и COOP/CORP;
* тело запроса ограничено 25 МБ (413);
* `PATCH /api/settings` и импорт принимают только известные секции; устаревший
  `auth` вырезается, а `config.json` создаётся с правами `0600`;
* все изменяющие действия — в `logs/audit.jsonl` (кто/что/когда/результат),
  журнал ротируется;
* песочница `Workspace.resolve` не выпускает за `MEGATOOL_HOME` и `extra_roots`;
  файлы наборов проверяются по относительному пути (`_safe_rel`: без `..`,
  `~`, `:` и абсолютных путей);
* аргументы внешних команд — через `safe_id` (белый список символов), без shell;
  параметры SSH-задач валидируются по регулярным выражениям;
* деструктивные настройки (`safety.allow_*`) позволяют запретить kill,
  удаление контейнеров, подов и файлов, удалённые операции;
* пробные режимы: `nginx -t`, `docker compose config`, `kubectl --dry-run`,
  dry-run SSH-скриптов.
