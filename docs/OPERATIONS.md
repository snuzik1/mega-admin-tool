# Эксплуатация MegaTool

Документ для повседневной эксплуатации v0.9.0: здоровье, удалённый доступ и
TLS, журналы, резервные копии, обновления и восстановление. Все команды — для
Linux; путь `~/.megatool` замените на свой `MEGATOOL_HOME`.

## Здоровье и наблюдаемость

- `GET /api/health` — публичная проверка живости. Возвращает версию, uptime,
  состояние мониторинга и подсказки о нехватке инструментов. Подходит для
  systemd watchdog, Docker `HEALTHCHECK`, внешнего монитора и балансировщика.
- `GET /api/state` — полное состояние; требует сессию. Используйте для
  дашбордов после входа, а не для liveness-проб.
- WebSocket `/api/ws/metrics` — поток метрик; закрывается кодом `4401` без
  сессии. Подходит для браузера, не для внешнего мониторинга без cookie.
- `logs/audit.jsonl` — входы, выходы, изменения настроек и опасные действия.
  Файл ротируется приложением; не содержит паролей.
- `runs/<job>.log` — логи фоновых задач (Ansible, SSH, compose). Не входят в
  резервную копию по умолчанию.
- systemd: `journalctl --user -u megatool -f`; для системной службы —
  `journalctl -u megatool -f`. Уровень логирования задаётся `--log-level`.

Проверка вручную:

```bash
curl -fsS http://127.0.0.1:8787/api/health | python3 -m json.tool
# если включён встроенный HTTPS:
curl -kfsS https://127.0.0.1:8787/api/health | python3 -m json.tool
.venv/bin/python -m megatool --auth-status
```

Не делайте `/api/health` единственным сигналом: он не проверяет доступность
Docker, Kubernetes или внешних серверов. Для этого используйте раздел
**Проверки сервисов** и алерты.

## Удалённый доступ и TLS

Встроенный TLS включён, когда `server.tls.enabled = true`; uvicorn принимает
HTTPS сам, reverse proxy не обязателен. Внешний bind (`0.0.0.0`/`::`) без TLS
не запускается. Явное исключение — `--allow-insecure-remote` или
`MEGATOOL_ALLOW_INSECURE_REMOTE=1`; используйте его только в изолированной
сети, не в интернете. Docker-образ содержит этот флаг, потому что внутри
контейнера bind всегда `0.0.0.0`; публикуйте его порт только на loopback.

### Мастер настройки

```bash
sh run.sh --setup
```

Мастер предлагает локальный HTTP или LAN HTTPS. Для LAN он:

* ставит `server.host = 0.0.0.0`, `server.tls.enabled = true`;
* создаёт самоподписанный сертификат и ключ в `tls/` рядом с `config.json`
  (обычно `$MEGATOOL_HOME/tls/`), если сертификата ещё нет (или просит
  пересоздать существующий);
* печатает LAN-адреса, SHA-256 отпечаток и напоминание про firewall.

Сертификат содержит SAN для `localhost`, loopback, имени машины, локальных
IP, адреса привязки и `server.allowed_hosts`. Для доступа по своему DNS-имени
добавьте его в настройках **до** генерации сертификата (или пересоздайте
сертификат). Самоподписанный сертификат нужно импортировать в доверенные на
клиенте; иначе браузер покажет предупреждение.

### Собственный сертификат

Укажите оба файла — через CLI или `server.tls`:

```bash
sh run.sh --tls-cert /etc/megatool/tls/server.crt \
          --tls-key  /etc/megatool/tls/server.key
```

Ключ должен принадлежать пользователю MegaTool, иметь права `0600`; каталог
ключа должен быть приватным (`0700`). Симлинки не принимаются.
Для Let's Encrypt настройте deploy-hook, который копирует `fullchain.pem` и
`privkey.pem` в закрытый каталог и перезапускает MegaTool; автоматического
перечитывания сертификата нет. После замены файлов перезапустите службу.

### Сеть и firewall

MegaTool не меняет правила firewall. Разрешите только нужный порт и, по
возможности, только доверенные подсети. Примеры:

```bash
sudo ufw allow from 192.168.0.0/24 to any port 8787 proto tcp
sudo firewall-cmd --add-port=8787/tcp --permanent && sudo firewall-cmd --reload
```

Проверка Host включена всегда: локальные IP и имя машины разрешены
автоматически, дополнительное DNS-имя добавьте в `server.allowed_hosts`.
Если перед MegaTool всё же стоит reverse proxy, сохраняйте исходный `Host` и
схему (`X-Forwarded-Proto`), иначе cookie `Secure`/Origin-проверки будут
работать неверно. Встроенный TLS предпочтительнее для прямого доступа.

### Проверка

```bash
curl -kfsS https://127.0.0.1:8787/api/health
openssl s_client -connect 127.0.0.1:8787 -servername localhost </dev/null
```

`/api/health` публичен; после проверки TLS откройте интерфейс и войдите как
`admin`. HSTS приходит только по HTTPS.

## Резервное копирование

Остановите изменения на время копирования (или снимите snapshot ФС):

```bash
.venv/bin/python scripts/backup.py --output /var/backups/megatool-$(date +%F).tgz
```

По умолчанию архив включает `config.json`, `hosts_state.json`, `auth.json`,
`apps/`, `bundles/`, `configs/` и `tls/` (сертификат и приватный ключ).
`logs/` и `runs/` добавляются флагами `--include-logs` и `--include-runs`.
Архив создаётся эксклюзивно (`O_EXCL`) с правами `0600` уже во время записи,
потому что содержит хеш пароля и ключ TLS; храните его как секрет и шифруйте
при передаче. Существующий файл не перезаписывается. Если `certfile`/`keyfile`
указывают за пределы `MEGATOOL_HOME` (например, Let's Encrypt), скопируйте их
отдельно: в архив попадает только каталог `tls/`.

Восстановление — только на остановленный MegaTool:

```bash
systemctl --user stop megatool       # или Ctrl+C в ручном запуске
.venv/bin/python scripts/restore.py /var/backups/megatool-2026-10-25.tgz --force
systemctl --user start megatool
```

Скрипт отклоняет абсолютные пути, `..`, симлинки и устройства, а также не
записывает через уже существующие симлинки в `MEGATOOL_HOME`; существующий
каталог `MEGATOOL_HOME` должен иметь права `0700` (иначе будет подсказка
`chmod 700`). `auth.json`, `config.json` и все файлы внутри `tls/`
принудительно получают `0600`, а `tls/` и его подкаталоги — `0700`. После восстановления
проверьте, что `server.tls.enabled` соответствует наличию сертификата; при
отсутствии ключа приложение откажется стартовать (fail closed), а не откроет
порт без TLS.
Проверьте вход после восстановления: сессии в памяти не сохраняются, поэтому
потребуется пароль. Восстановление не транзакционно: при нехватке места или
ошибке копирования часть файлов может остаться обновлённой. Перед ним снимите
свежую резервную копию; `--force` перезаписывает совпадающие пути, но не
удаляет файлы, которых нет в архиве. Запускайте `restore.py` от того же
пользователя, что и MegaTool: после восстановления от root файлы получат
владельца root, и служба пользователя откажется их читать.

## Обновление и откат

1. Прочитайте [CHANGELOG.md](../CHANGELOG.md) и сделайте резервную копию.
2. Остановите службу/процесс.
3. Обновите код: `git fetch --tags && git checkout v0.9.0` (или запустите
   `sh quickstart.sh` с `MEGATOOL_UPDATE=1` для управляемой установки).
4. Запустите `sh run.sh`/`python3 start.py` — зависимости обновятся в `.venv`.
5. Проверьте `/api/health`, вход и один безопасный раздел (например,
   **Обзор**). Затем верните службу в строй.

Откат: остановите процесс, `git checkout <предыдущий тег>`, при необходимости
восстановите архив, запустите снова. `auth.json` версии 1 совместим в пределах
0.8.x–0.9.x; при переходе на новую major-версию смотрите примечания к релизу.
Не откатывайтесь на версию, которая ещё не знала `auth.json`, без резервной
копии: старый код проигнорирует файл.

Политика версий: до 1.0 допускаются изменения поведения в minor-релизах, но
формат `config.json` и `auth.json` мигрируется автоматически или явно
описывается в CHANGELOG. Критические исправления безопасности выпускаются
отдельным patch-релизом.

## Контейнер

```bash
docker build -t megatool:0.9.0 .
docker volume create megatool-data

# Первый запуск: пароль вводится в терминале и не попадает в env/history.
docker run --rm -it -p 127.0.0.1:8787:8787 \
  -v megatool-data:/data \
  megatool:0.9.0

# Дальше — без секрета в окружении; вход выполняется в браузере.
docker run -d --name megatool -p 127.0.0.1:8787:8787 \
  -v megatool-data:/data --restart unless-stopped megatool:0.9.0
```

Образ работает от непривилегированного пользователя (uid 10001) и слушает
`0.0.0.0` внутри контейнера; entrypoint передаёт `--allow-insecure-remote`,
потому что иначе контейнерный bind был бы запрещён. Это **не** делает
публикацию порта безопасной: по умолчанию публикуйте только
`127.0.0.1:8787:8787`. Для доступа с других машин рекомендуется native
установка со встроенным TLS (`--setup`), а не открытый Docker-порт. Если
контейнер всё же должен отдавать HTTPS, смонтируйте сертификат/ключ с
владельцем 10001 и правами `0600`, включите `server.tls` в `/data/config.json`
и перезапустите контейнер; healthcheck автоматически переключится на HTTPS.
При доступе к контейнеру по внешнему IP или DNS-имени добавьте его в
`server.allowed_hosts`: внутри контейнера видны только его собственные
интерфейсы, поэтому строгий Host guard иначе ответит `421`.

Каталог `/data` имеет права `0700`; при bind-mount самостоятельно выполните
`chown 10001:10001` и `chmod 700` на хосте. Для автоматического первого
запуска можно один раз передать `MEGATOOL_ADMIN_PASSWORD` через секрет
orchestrator'а, но не храните его в compose-файле, истории shell или
`docker inspect`. `HEALTHCHECK` использует публичный `/api/health` и
проверяет TLS без проверки самоподписанного сертификата. Если TLS
терминирует внешний прокси, сохраняйте исходный `Host`
(`ProxyPreserveHost On` / `proxy_set_header Host $host`), а cookie `Secure`
включайте через `MEGATOOL_SECURE_COOKIE=1`; при встроенном TLS это не нужно.

## Ограничения и аварийные ситуации

- **Забыт пароль:** остановите MegaTool, удалите `auth.json`, запустите снова
  и задайте новый пароль. Все сессии станут недействительны. Root может
  удалить файл независимо от владельца.
- **Неверные права или владелец `auth.json`/каталога:** приложение откажется
  стартовать и попросит `chmod 600`/`chmod 700` либо запуск от владельца.
  Не запускайте с `--no-login-prompt`, пока не исправите права.
- **Нет `auth.json` в systemd/контейнере:** запуск завершится ошибкой
  (fail closed). Создайте файл в терминале или через одноразовый
  `MEGATOOL_ADMIN_PASSWORD`.
- **TLS не стартует / порт не открывается:** проверьте `server.tls.enabled`,
  пути `server.tls.certfile`/`keyfile`, права (`key` — `0600`, каталог —
  `0700`, владелец — пользователь MegaTool), срок действия и SAN сертификата.
  Внешний bind без TLS намеренно завершается ошибкой; включите TLS или явно
  разрешите insecure-режим только для изолированного стенда.
- **Самоподписанный сертификат:** браузер предупредит; импортируйте
  `server.crt` в доверенные либо используйте сертификат от доверенного CA.
  После пересоздания сертификата старый отпечаток в клиенте нужно заменить.
- **Переполнение диска:** следите за `runs/`, `logs/` и резервными копиями;
  ограничьте число задач в настройках (`jobs.max_active`, `jobs.keep`).
- **Python 3.8:** поддержка сохранена, но исправления Starlette требуют
  Python 3.10+. См. «Известные ограничения зависимостей» в
  [SECURITY.md](../SECURITY.md); для внешнего периметра используйте Python
  3.10+ и обновлённые зависимости после проверки.
- **Доступность интерфейса:** экран входа проверен Lighthouse (Accessibility /
  Best Practices / SEO — 100), клавиатурная навигация и `role="alert"` для
  ошибок сохранены. Основные разделы остаются обычными HTML-формами.
