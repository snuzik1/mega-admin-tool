## [0.9.0] — 2026-10-26

### Добавлено

- **Встроенный HTTPS без обязательного reverse proxy.** MegaTool запускает
  uvicorn с `ssl_certfile`/`ssl_keyfile`; включается через `server.tls.enabled`.
  Поддерживаются самоподписанный сертификат и собственные PEM-файлы.
- `megatool/tls.py`: пути по умолчанию (`$MEGATOOL_HOME/tls/server.crt` и
  `server.key` рядом с `config.json`), проверка владельца/прав/симлинков,
  загрузка пары через
  `ssl.SSLContext`, SHA-256 отпечаток, срок действия, SAN для loopback, имени
  машины, локальных IP, адреса привязки и `allowed_hosts`.
- Генерация самоподписанного сертификата через `openssl` (RSA 3072, SHA-256,
  825 дней, `serverAuth`): приватный ключ `0600`, сертификат `0644`, каталог
  `0700`, атомарная замена файлов. При отсутствии `openssl` — понятная ошибка.
- Мастер `--setup`: локальный HTTP на `127.0.0.1` или LAN HTTPS на `0.0.0.0`;
  печатает LAN-адреса, SHA-256 отпечаток, предупреждение о доверии браузера и
  необходимости открыть порт в firewall. Firewall автоматически не меняется.
- CLI: `--tls-cert`, `--tls-key`, `--allow-insecure-remote`; переменная
  `MEGATOOL_ALLOW_INSECURE_REMOTE`. Пара `--tls-cert`/`--tls-key` обязательна,
  пути сохраняются в `server.tls`; при неверной паре запуск отклоняется.
- Политика внешнего bind: `0.0.0.0`/`::` без TLS завершается ошибкой при
  запуске; `PATCH /api/settings` и импорт настроек также не позволяют
  сохранить такой адрес. Исключение — явный флаг/переменная окружения.
- `server.allowed_hosts` теперь работает и при внешнем bind; автоматически
  добавляются loopback, имя машины, локальные IP и адрес привязки. HSTS
  (`max-age=31536000`) добавляется к HTTPS-ответам.
- API и интерфейс: `GET /api/settings` отдаёт статус TLS, пути, отпечаток,
  срок действия и ошибку; `POST /api/settings/tls/generate` создаёт
  сертификат и включает HTTPS; в настройках — карточка TLS с путями к своим
  PEM-файлам, генерацией, включением и выключением (после изменения требуется
  перезапуск).
- `install.sh` ставит `openssl` и `ca-certificates`; Docker-образ содержит их
  и использует TLS-aware `HEALTHCHECK`; systemd-скрипт определяет схему и
  адрес из конфигурации, печатает HTTPS URL и добавляет `UMask=0077`.
- `scripts/backup.py`/`restore.py` включают каталог `tls/`; при восстановлении
  все файлы внутри него получают `0600`, а `tls/` и подкаталоги — `0700`.
- Тесты: `tests/test_tls.py` (генерация, SAN, права, отпечаток, ошибки,
  политика bind) и `tests/test_remote_access.py` (внешний bind, API TLS,
  Host allowlist, HSTS, генерация и включение TLS). Backup-тест проверяет
  сохранение TLS-ключа и его прав.
- README, `docs/OPERATIONS.md`, `docs/GUIDE.md`: удалённый доступ, мастер,
  собственные сертификаты, firewall, Let's Encrypt/deploy-hook, Docker и
  ограничения.

### Изменено

- Обновление с 0.8.x: если раньше `server.host` был внешним (`0.0.0.0`/`::`),
  запуск теперь требует TLS (`sh run.sh --setup` или свои `--tls-cert`/
  `--tls-key`) либо явного `--allow-insecure-remote`/`server.allow_insecure_remote`.
  Локальный режим `127.0.0.1` не меняется.
- Проверка Host больше не отключается при внешнем bind. Своё DNS-имя нужно
  добавить в `server.allowed_hosts`; локальные IP и имя машины разрешены
  автоматически.

### Безопасность

- Внешний bind без TLS закрыт по умолчанию (fail closed) — в CLI, API и при
  импорте настроек. Небезопасный режим требует явного подтверждения.
- Проверка Host не отключается при внешнем bind; добавлена HSTS для HTTPS.
- TLS-ключ проверяется по владельцу и правам `0600`, каталог ключа должен быть
  приватным (`0700`, без доступа группы/остальных); симлинки отклоняются. Это
  защищает от подмены ключа и случайного расширения доступа.
- Docker-образ по-прежнему слушает `0.0.0.0` внутри контейнера и содержит
  `--allow-insecure-remote`, поскольку иначе контейнер не смог бы принять
  опубликованный порт. Публикуйте порт только на `127.0.0.1`; для удалённого
  доступа рекомендуется native install со встроенным TLS.
- Известное ограничение Python 3.8: часть advisories Starlette нельзя
  исправить без повышения минимальной версии; см. `SECURITY.md`. Для внешнего
  периметра используйте Python 3.10+.

## [0.8.0] — 2026-10-26

### Добавлено

- **Встроенная аутентификация MegaTool**: одна учётная запись `admin` с полным
  доступом. Пароль задаётся в терминале при первом запуске и запрашивается при
  следующих; в браузере добавлен экран входа, кнопка выхода и обработка
  истечения сессии. Пароль хранится только как PBKDF2-SHA256-хеш (600 000
  итераций) в `~/.megatool/auth.json` (`0600`, каталог `0700`).
- Закрыты все `/api/*`, кроме `/api/health`, `/api/auth/status` и
  `/api/auth/login`, а также WebSocket-маршруты; без сессии API отвечает `401`,
  сокет закрывается кодом `4401`. Cookie сессии — `HttpOnly`,
  `SameSite=Strict`, срок 12 часов; не более 5 неудачных попыток входа за
  60 секунд. Вход и выход пишутся в журнал аудита.
- CLI: `--set-password`, `--auth-status`, `--no-login-prompt`, `--auth-file`;
  переменные `MEGATOOL_AUTH_FILE`, `MEGATOOL_ADMIN_PASSWORD`,
  `MEGATOOL_NEW_PASSWORD`, `MEGATOOL_AUTH_ITERATIONS`,
  `MEGATOOL_SECURE_COOKIE`, `MEGATOOL_NO_LOGIN_PROMPT`.
- `scripts/install-autostart.sh` проверяет наличие `auth.json`, передаёт
  systemd пути `MEGATOOL_HOME`/`MEGATOOL_AUTH_FILE` и запускает службу с
  `--no-login-prompt`; smoke-скрипт проверяет `401` без входа и успешный вход.
- Тесты аутентификации: права файла, хеш без открытого пароля, вход/выход,
  rate limit, urlencoded-форма, закрытый API и WebSocket, живой uvicorn с
  cookie. Общий тестовый клиент входит один раз.
- `quickstart.sh` — запуск одной командой на чистой Linux-машине или VM:
  скачивает tar.gz с GitHub без git в `~/.local/share/megatool`, поддерживает
  `MEGATOOL_INSTALL_DIR`, `MEGATOOL_REF`, `MEGATOOL_UPDATE=1` и передаёт
  аргументы в `run.sh`. Повторный запуск использует уже скачанный код.
- `install.sh` — автоматическая установка системных предпосылок для запуска:
  определяет apt-get, dnf/yum, pacman, apk или zypper, использует `sudo`
  только при необходимости и на Alpine доставляет `build-base`,
  `linux-headers` и `python3-dev`. Docker, kubectl, Ansible, nginx и SSH
  остаются необязательными и не устанавливаются.
- `run.sh` переведён на POSIX `sh` и при отсутствии Python 3.8+/venv сам
  вызывает `install.sh --system-only`; работает на минимальном Alpine без
  предустановленного `bash`. Автоустановку можно отключить через
  `MEGATOOL_AUTO_INSTALL=0`.
- `start.py --install-only` готовит `.venv` и runtime-зависимости без запуска
  сервера; при неудачном создании venv или установке pip `start.py` также
  пытается доставить системные пакеты через `install.sh`.
- CI проверяет POSIX-синтаксис установщика и quickstart (включая скачивание,
  распаковку и повторный запуск), а также smoke в чистом Alpine-контейнере,
  где `run.sh` устанавливает пакеты сам.
- Интерфейс перенесён в `megatool/web/` и включён в wheel как package-data;
  CI собирает wheel, проверяет наличие HTML/CSS/JS и импорт `WEB_DIR` из
  установленного пакета.
- `MEGATOOL_VENV` теперь учитывают `scripts/bootstrap.sh` и
  `scripts/install-autostart.sh`, а не только `start.py`.
- Подсказка по установке для Alpine (`python3`, `py3-pip`, `bash`) и
  smoke-проверка в контейнере Alpine 3.20.
- `scripts/venv_path.py` — единое разрешение относительных путей, `~` и
  переменных окружения для shell-скриптов.
- `scripts/backup.py` и `scripts/restore.py`: безопасная резервная копия
  `config.json`/`auth.json`/приложений/наборов и восстановление с проверкой
  путей, типов файлов и прав `0600`/`0700`. Архив с хешем пароля создаётся
  с правами `0600`; `..`, симлинки и устройства отклоняются.
- `docs/OPERATIONS.md`: health, журналы, backup/restore, обновление и откат,
  контейнер, аварийные ситуации. Добавлен `Dockerfile` с непривилегированным
  пользователем, `HEALTHCHECK` и volume `/data`; CI собирает образ.
- Coverage-гейт 60% (`pytest-cov`) и отдельная CI-задача безопасности:
  Bandit (только high) и pip-audit с задокументированными исключениями
  Starlette. `scripts/security_audit.sh` и `requirements-security.txt`.
- README: раздел о переезде с Windows/macOS на WSL2/Linux, объяснение
  `MEGATOOL_VENV` и политики Python 3.8.

### Исправлено

- `start.py --version` и `--help` теперь работают на любой ОС, как и
  `python -m megatool --version`; реальный запуск по-прежнему требует Linux.
- Понятная ошибка при попытке использовать Windows-venv (`Scripts/python.exe`)
  в Linux, вместо невнятного сбоя `.venv/bin/python`.
- `scripts/jscheck.py` ищет ES-модули в `megatool/web/js` независимо от
  текущего каталога запуска.
- `util.atomic_write` использует уникальный временный файл: параллельная
  запись статуса задачи из исполнителя и `cancel` больше не теряет
  `FileNotFoundError`; отмена задачи в состоянии `pending` срабатывает сразу.
- Работающий сервер замечает изменение/удаление `auth.json`: смена пароля через
  `--set-password` и восстановление из архива применяются без перезапуска,
  а прежние HTTP- и WebSocket-сессии отзываются.
- Smoke-скрипт и systemd-юнит учитывают `MEGATOOL_HOME`/`MEGATOOL_AUTH_FILE`,
  в том числе пути с пробелами.

### Изменено

- Документация (README, SECURITY, ARCHITECTURE, GUIDE, ROADMAP) переведена на
  модель с одной учётной записью; удалены утверждения об отсутствии входа.
- `start.py`/`run.sh` и прежний быстрый запуск сохранены; при первом запуске
  добавляется только запрос пароля. `--help`, `--version`, `--install-only` и
  симуляция запуска не требуют TTY.
- Версия поднята до 0.8.0.

### Безопасность

- Пароль не хранится в открытом виде; `auth.json` создаётся атомарно с правами
  `0600`, каталог — `0700`, при чтении отклоняются чужой владелец,
  групповой/остальной доступ и символические ссылки.
- Веб-сессии в памяти, `HttpOnly`/`SameSite=Strict`, ограничение попыток входа,
  лимит тела входа 64 KiB (включая chunked), аудит входов/выходов; API и
  WebSocket fail closed без сессии.
- Неинтерактивный запуск без `auth.json` завершается ошибкой, а не открывает
  сервер; systemd требует предварительно созданный файл секрета.
- `ip_hash` переведён с SHA-1 на SHA-256 (Bandit B324).
- Проверяются права не только `auth.json` (`0600`), но и каталога (`0700`);
  чужой владелец, групповой или остальной доступ отклоняются, а не молча
  chmod-ятся. API не кэшируется (`Cache-Control: no-store`), слишком длинный
  пароль на входе отклоняется до PBKDF2.
- `Origin` изменяющих запросов и WebSocket сверяется с `Host` и портом, а не
  только с именем: другое localhost-приложение не сможет выполнить CSRF, а
  проверка остаётся включённой при внешнем bind.
- Экспорт балансировщика с записью файла вынесен в `POST`; `GET` отдаёт только
  предпросмотр, поэтому ссылка/картинка с другого localhost-порта не может
  изменить конфиг.
- `scripts/backup.py` создаёт архив эксклюзивно (`O_EXCL`) и сразу с `0600`,
  не перезаписывая существующий файл; `scripts/restore.py` не пишет через
  существующие симлинки внутри `MEGATOOL_HOME`.
- `pip-audit` фиксирует шесть advisories Starlette, исправления которых требуют
  Python 3.9/3.10. Исключения явно перечислены в `SECURITY.md` и
  `scripts/security_audit.sh`; новые advisories валят CI.
- Экран входа: `main`-landmark, readonly-поле `admin`, `aria-describedby` и
  `aria-busy`, meta description; Lighthouse Accessibility/Best Practices/SEO —
  100.

## [0.7.0] — 2026-10-22

### Добавлено

- Поддержка **Python 3.8+**: аннотации переведены на `typing`, добавлены
  совместимые `util.is_within()` и `util.write_text()`, версия Python
  проверяется в `start.py` и в CI (3.8/3.12/3.14).
- Кэш шаблонов серверных переводов (`i18n.py`) и кэш разбора точечных путей
  настроек (`config.py`).
- Единый запуск на Linux: `start.py` — единственная точка подготовки `.venv`
  при обычном запуске; `run.sh` только делегирует ему аргументы. `--help`
  и `--version` не создают окружение и не вызывают pip.
- Симуляция запуска на 10 Linux-профилях (`scripts/startup_matrix.py` + pytest)
  с проверкой пути `bin/python`, установки зависимостей и флагов.
- CI-матрица: Ubuntu с Python 3.8/3.12/3.14, плюс smoke-проверка
  `python start.py --version` и `bash run.sh --version`.

### Изменено

- HTTP-middleware безопасности объединены в один проход: проверка `Host`,
  `Origin`, лимит тела и заголовки безопасности.
- `PATCH /api/settings` и импорт принимают только известные секции; старый
  ключ `auth` вырезается при загрузке, обновлении и экспорте.
- Зависимости закреплены диапазонами, совместимыми с Python 3.8.
- Документация, GUIDE, ARCHITECTURE, ROADMAP, SECURITY и CONTRIBUTING обновлены
  под новую модель доступа и версию Python.
- Интерфейс стал понятнее: уточнены названия разделов, добавлена панель
  «Инструменты» со статусом Docker/Podman/kubectl/Ansible/SSH, справка по `F1`,
  сворачиваемый блок «Среда» и единые заголовки страниц.

### Удалено

- Система доступа целиком: `access.py`, `api_access.py`, `localauth.py`,
  раздел «Доступ», пользователи, пресеты прав, сессии, мастер-токен, токен
  доступа и окна входа/смены пароля. Токены удалённых агентов мониторинга
  сохранены как отдельный механизм.
- Связанные серверные и клиентские строки локализации и тесты доступа.
- Поддержка Windows и macOS: обёртки `start.cmd`/`run.ps1`, PowerShell-скрипты
  bootstrap и автозапуска, платформенные ветки в backend и агенте, профили CI
  и симуляции запуска, Windows/macOS-подсказки в интерфейсе.
- Зависимости от API Python 3.9+: `Path.is_relative_to`,
  `write_text(newline=...)`, `cancel_futures`.

### Безопасность

- Сохранены проверки `Host`/`Origin`, CSP и заголовки безопасности, лимит тела
  запроса, песочница файлов и аудит изменяющих действий.
- Удалённый доступ рекомендуется через VPN, SSH-туннель или обратный прокси
  с аутентификацией; в 0.7.0 встроенной проверки пароля/токена не было
  (одна учётная запись возвращена в 0.8.0).

## [0.6.0] — 2026-10-21

### Добавлено

- Первый **владелец MegaTool**: отдельный логин и пароль, полный пресет
  «Администратор», флаг `owner` и защита последнего включённого владельца.
- Мастер первого запуска: loopback, пустой список пользователей и проверка
  root/sudo/администратора у процесса; логин MegaTool вводится оператором.
- Иерархия доступа: только владелец создаёт администраторов и других владельцев,
  меняет административные пресеты и аккаунты владельцев.
- `auth.local_only`: привязка пользователей к локальным root/администраторам и
  повторная проверка при входе.
- Смена собственного пароля со старым паролем и отзывом всех сессий.
- Краткие инструкции по всем 15 разделам — [docs/GUIDE.md](docs/GUIDE.md).
- GitHub Actions CI для Linux, шаблоны Issue/PR, Dependabot,
  политика безопасности и руководство по публикации.

### Изменено

- Раздел «Доступ» показывает владельца, локальную учётную запись и её роль;
  административные действия скрыты от обычных администраторов.
- Мастер-токен и карточка «Локальные пользователи» находятся на вкладке
  **Настройки → Сервер**.
- Локальные пользователи и пресеты прав вынесены в отдельный слой RBAC;
  неизвестные API-маршруты по-прежнему требуют `settings:manage`.

### Безопасность

- Пароли MegaTool хранятся как PBKDF2-SHA256-хэши в `access.json` с правами
  `0600`; сброс чужого пароля через CRUD пользователей запрещён.
- Ограничены создание и изменение административных пресетов, попытки повышения
  привилегий и удаление последнего владельца.
- Проверки Host/Origin, CSP, лимит запросов и аудит опасных действий сохранены.

### Исправлено

- Первый владелец не может остаться без доступа к управлению пользователями:
  его пресет обязан давать управление и разделом «Доступ», и настройками.
- Обычный администратор может менять обычные пресеты, не затрагивая
  административные, которые присутствуют в общем payload.
