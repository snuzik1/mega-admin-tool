# Политика безопасности

## Поддерживаемые версии

| Версия | Поддержка |
| --- | --- |
| `0.9.x` | да |
| `0.8.x` | ограниченно |
| `0.7.x` и старше | по возможности |

MegaTool развивается как self-hosted инструмент администратора. Перед
публикацией релиза проверяйте, что используете последнюю версию из этого
репозитория.

## Как сообщить об уязвимости

**Не открывайте публичный Issue для уязвимости.** Используйте приватный отчёт:

1. Откройте вкладку **Security** репозитория на GitHub.
2. Нажмите **Report a vulnerability** и заполните приватный security advisory.
3. Если кнопка недоступна, свяжитесь с мейнтейнерами через их профили GitHub,
   не раскрывая детали в публичном обсуждении.

В отчёте полезно указать:

- версию MegaTool и ОС;
- шаги воспроизведения;
- ожидаемое и фактическое поведение;
- потенциальное влияние;
- минимальный PoC без реальных токенов агентов и приватных ключей.

Не прикладывайте `config.json`, токены агентов, SSH-ключи и другие секреты.
Если секрет уже попал в отчёт, сразу отзовите его.

## Что входит в область проверки

- XSS, CSRF, DNS-rebinding (Host/Origin), CSWSH и утечка токенов агентов;
- ошибки встроенного TLS: проверка сертификата/ключа, права, SAN, подмена
  файлов, небезопасный внешний bind, HSTS;
- обход входа, подбор пароля, кража/фиксация сессии, ошибки в `auth.json`;
- path traversal и выход за разрешённые каталоги;
- повышение привилегий через API, настройки или редактор файлов;
- RCE и инъекции при работе с внешними командами;
- ошибки, приводящие к выполнению команд от имени root/администратора;
- обход ограничений `safety.allow_*` и песочницы `Workspace`.

Вне области — уязвимости в Docker, Kubernetes, Ansible, nginx, SSH и других
внешних инструментах. Сообщайте о них их разработчикам.

## Модель безопасности

MegaTool по умолчанию слушает только `127.0.0.1`. Встроенная аутентификация
включена всегда: одна учётная запись администратора с полным доступом, без
ролей и разделения прав. Это сознательно простая модель для self-hosted
консоли одного оператора. Для внешнего доступа используется встроенный TLS;
внешний bind без TLS отклоняется, если администратор явно не разрешил
insecure-режим для изолированного стенда.

### Пароль и файл секрета

- Пароль задаётся в терминале при первом запуске (не короче 8 символов) и
  хранится только как PBKDF2-SHA256-хеш с 16-байтовой солью и 600 000
  итераций. Открытый пароль не пишется в `config.json`, экспорт, логи или API.
- По умолчанию файл — `~/.megatool/auth.json`; путь переопределяется
  `MEGATOOL_AUTH_FILE` или `--auth-file`. Файл создаётся атомарно с правами
  `0600`; новый каталог — `0700`. При чтении проверяются регулярность файла,
  отсутствие группового/остального доступа, владелец и права каталога;
  символические ссылки и чужие файлы отклоняются. При неверных правах
  приложение не стартует и подсказывает `chmod 600`/`chmod 700`. Каталог
  `0700` обязателен и для `--auth-file`, и для `MEGATOOL_HOME`.
- Приложение принимает только файл и каталог, принадлежащие текущему
  пользователю (root — только `root:root`). Root имеет доступ к файлу на
  уровне ОС, но запуск консоли от root не рекомендуется: если файл принадлежит
  другому пользователю, проверка владельца не даст его использовать. Буквально
  «только root» возможно при запуске MegaTool от root с файлом `root:root 0600`;
  для выделенного служебного пользователя файл должен принадлежать ему.
- Потеря пароля означает сброс: остановить процесс, удалить `auth.json`
  (root может это сделать независимо от владельца) и задать новый пароль при
  следующем запуске. Все веб-сессии при этом становятся недействительными.

### Сессии и вход

- Терминальный вопрос задаётся только при наличии TTY. Для systemd, CI и
  контейнеров есть `--no-login-prompt`/`MEGATOOL_NO_LOGIN_PROMPT=1`: он
  пропускает только терминальный вопрос, веб-вход остаётся обязательным.
  Если `auth.json` отсутствует, неинтерактивный запуск завершается ошибкой
  (fail closed), а не поднимает открытый сервер.
- Сессии хранятся в памяти процесса (12 часов, до 32 штук) и исчезают при
  перезапуске. Сервер проверяет mtime/права `auth.json`: смена пароля,
  восстановление файла или его удаление отзывают все сессии без перезапуска;
  открытые WebSocket-потоки также перепроверяют сессию. Cookie
  `megatool_session` — `HttpOnly`, `SameSite=Strict`, `Path=/`; при встроенном
  HTTPS флаг `Secure` выставляется автоматически, а за внешним HTTPS-прокси
  включайте `MEGATOOL_SECURE_COOKIE=1`.
- Без сессии все `/api/*`, кроме `/api/health`, `/api/auth/status` и
  `/api/auth/login`, возвращают `401`; WebSocket закрывается кодом `4401`.
  Ответы API отдаются с `Cache-Control: no-store`, чтобы конфиги и результаты
  команд не оставались в кэше браузера или прокси.
- Не более 5 неудачных попыток входа за 60 секунд с одного адреса; успешный
  вход сбрасывает счётчик. Тело запроса входа ограничено 64 KiB, в том числе
  при chunked-передаче без `Content-Length`. Вход и выход пишутся в журнал
  аудита без пароля.
- Ограничения: нет MFA, восстановления по email, нескольких пользователей и
  ролей. Для периметра с недоверенными пользователями используйте внешний
  аутентифицирующий прокси и отдельные ОС-учётные записи.

### Сеть и TLS

Для внешнего доступа включите встроенный HTTPS (`--setup`, настройки или
`--tls-cert`/`--tls-key`). Внешний bind без TLS завершается ошибкой, кроме
явного `--allow-insecure-remote`/`MEGATOOL_ALLOW_INSECURE_REMOTE=1` для
изолированного стенда. TLS-ключ должен принадлежать пользователю MegaTool,
иметь права `0600`, а каталог — `0700`; симлинки отклоняются. Сертификат можно
создать самоподписанным или использовать доверенный; автоматического
продления нет. HTTPS-ответы получают HSTS. Даже с TLS ограничивайте порт
firewall/VPN и не публикуйте консоль в интернет без необходимости.
Действия выполняются с правами ОС-пользователя процесса, поэтому запускайте
MegaTool только на доверенной машине.

`run.sh`/`start.py` могут автоматически вызвать `install.sh` для недостающих
системных пакетов Python; установщик использует `sudo`, только если процесс
запущен не от root, и не ставит необязательные Docker/kubectl/Ansible/nginx/SSH.
Автоустановка отключается через `MEGATOOL_AUTO_INSTALL=0`. `quickstart.sh`
скачивает архив с GitHub по HTTPS и запускает `run.sh`; для воспроизводимости
указывайте в `MEGATOOL_REF` конкретный тег или коммит. Подробности — в разделе
«Аутентификация» в [README.md](README.md).

### Известные ограничения зависимостей

`pip-audit` сообщает о шести уникальных advisories в `starlette 0.48.0`
(`PYSEC-2026-161`, `PYSEC-2026-248`, `PYSEC-2026-249`, `PYSEC-2026-1942`,
`PYSEC-2026-2280`, `PYSEC-2026-2281`). Исправленные версии (`starlette>=0.49.1`
и `1.x`) требуют Python 3.9/3.10, а MegaTool 0.9.0 сознательно сохраняет
поддержку Python 3.8. Поэтому эти ID исключены из блокирующей проверки CI;
новые advisories по-прежнему валят сборку, а исключения пересматриваются при
переходе на Python 3.10+. Для периметра с повышенными требованиями запускайте
MegaTool на Python 3.10+ и ставьте обновлённый Starlette после проверки
совместимости FastAPI.
